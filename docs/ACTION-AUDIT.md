# Проверка действий интерфейса

Дата: 2026-09-15. Инвентаризация: `node server/test/button-inventory.mjs`.
Файл `button-inventory.json` содержит все кнопки исходного TSX с компонентом,
строкой, подписью и обработчиком, включая еще не подключенные демонстрационные экраны.
Это индекс для проверки, а не доказательство работоспособности каждой кнопки.

Подробная повторная проверка функций без внешних интеграций:
[INTERNAL-FUNCTIONAL-AUDIT.md](INTERNAL-FUNCTIONAL-AUDIT.md).

## Проверено с записью

- Проекты: создание с рекламодателями и без них; состояние сохраняется после перезагрузки.
- Материалы: пакетное сохранение, повторное сохранение, отдельное редактирование,
  загрузка файлов, отправка на модерацию, смена проекта.
- Заказы: создание со снимком материала, резервирование, прием паблишером,
  публикация, приемка заказчиком. Серверные тесты также проверяют отказ и спор.
- Площадки паблишера: создание через POST, сохранение полей и тарифов,
  открытие своей записи, редактирование через PUT. Активность меняется через API
  только после одобрения. Измененная площадка снова уходит на модерацию.
- Вход: отдельные кабинеты заказчика, паблишера и администратора; роль проверяется сервером.
- Лендинг доступен на `/` в том числе после входа; кнопка возвращает в свой кабинет.
- Админка: списки пользователей, рекламодателей, балансов, проводок и аудита читают базу.
  Карточка пользователя показывает доступную сумму, резерв и операции.
- Активность площадки меняется владельцем и администратором; заказчик видит только
  одобренные активные площадки. Деактивация не отменяет существующие заказы.
- Чат заказа, обращения в поддержку и ответы сохраняются на сервере.
  Переписка доступна участникам и администратору, чужие аккаунты получают 404.
- Споры получают короткий номер; администратор возвращает резерв или начисляет
  вознаграждение паблишеру. Повторное решение не проводит деньги повторно.
- Информеры создаются, публикуются и приостанавливаются через форму; учитывается
  период показа. Подборки используют действующие площадки из базы.
- Поиск заказов по короткому номеру работает у всех трех ролей (также с `№` или `#`).
- Сверка каждой учетной записи с дебетовыми и кредитовыми проводками покрыта тестом.
  Это проверка внутреннего учета, а не реального банковского перевода.

## Не завершено

Следующие действия нельзя считать рабочими только по изменению подписи кнопки:

| Раздел | Проблема |
| --- | --- |
| Настройки заказчика и паблишера | Кнопки сохранения части профиля закрывают локальную форму |
| Восстановление пароля и 2FA | Демонстрационные состояния, нет почтовой интеграции |
| Заявки паблишеров | Создание и приглашения не подключены к серверному процессу |
| Отчеты и экспорт админа | Часть кнопок только переключает «Экспорт готов» |
| Выплаты и пополнение | Нет платежного провайдера; тестовый внутренний баланс не является реальными деньгами |
| Управление пользователями и рекламодателями | Не все административные операции подключены |
| Настройки платформы | Есть локальные изменения без серверного сохранения |
| ИИ-генерация | Демонстрационные кнопки без поставщика услуги |
| Сезонные условия площадки | Дата начала пока отключена; поддерживаются коэффициент и скидка с датой окончания |

Нельзя выпускать эти действия как готовые и нельзя имитировать банковские,
почтовые или юридические операции фиктивным успешным ответом API.

## Локальные демоданные

Остановить локальный API перед `node server/local.mjs --seed-demo`.
Повторный вызов не создает дубликаты. Запуск в production запрещен.
Данные: 3 рекламодателя, 3 проекта, 8 материалов, 7 площадок, 7 заказов.
Кредит 3 млн рублей является только синтетическим балансом локальной базы.
Реквизиты и адреса `.example.test` вымышлены. Демо-подтверждения рекламодателей
не означают проверки организаций. Доступы: `.local-demo-accounts.json`, исключен из Git.

Адреса кабинетов: `/customer`, `/publisher`, `/admin`. Вход администратора:
`/admin/login`, без ссылки в публичном интерфейсе. На хостинге требуется SPA fallback.

После первоначального наполнения: остановить API и выполнить
`node server/local.mjs --seed-communications`, затем снова запустить API.
Команда добавляет два обращения в поддержку с ответами администратора и
переписку по демонстрационным спорам. Повторный запуск не создает дубликаты.

Браузерные проверки: `server/test/admin-operations-browser.mjs`,
`server/test/order-numbers-browser.mjs`, `server/test/informer-browser.mjs`.
Они используют локальные тестовые аккаунты; сообщения и тестовые информеры
сохраняются в локальной базе. API и Vite должны быть запущены.
