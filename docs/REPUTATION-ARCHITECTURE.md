# Репутационный мониторинг: утвержденная архитектура

Статус: утвержденная основа с уточнениями запуска от 2026-10-01.

## Цель и границы

Раздел «Репутация» собирает поисковую выдачу, публикации, ответы AI-сервисов,
данные доступных источников вокруг выбранного бренда, человека или компании.
TGStat и Ahrefs пока не подключены: их блоки не заполняются расчетными данными.
Собственный web crawler не разрабатывается. Brand Analytics и DataForSEO не используются.

Мониторинг публикаций строится по документам, найденным поисковыми API, и не
считается исчерпывающим мониторингом всего интернета. Период до 30 дней
применяется к поиску публикаций. Wordstat показывает частотность сохраненных
фраз, но не историческую динамику. Выдача и AI-ответы являются снимком на
момент запуска сканирования.

## Источники

| Задача | Сервис | Результат |
| --- | --- | --- |
| Выдача и публикации Яндекса | Yandex Search API v2 | До 100 результатов отдельно на каждый сохраненный запрос: URL, заголовок, сниппет и позиция |
| Ответ Alice AI | Yandex Search API Generative Search | Генеративный ответ и использованные источники |
| Выдача и AI-ответ Google | SerpApi | Отдельный запрос на каждую сохраненную фразу: органическая выдача, Markdown и доступный AI Overview |
| Ответ ChatGPT | OpenRouter | Отдельный от анализа материалов общий ответ по собранной поисковой выдаче |
| Backlinks и ссылочные сети | Ahrefs Site Explorer API | Отложено до подключения |
| Telegram | TGStat API | Отложено до подключения |
| Поисковый спрос | Wordstat API | Отдельная частотность только по сохраненным фразам, не более пяти |
| Полные тексты | Firecrawl Scrape API | Извлеченный текст и метаданные доступной страницы |
| Семантический анализ | OpenRouter, OpenAI-compatible Chat Completions API | Релевантность, тип источника, тональность, тематики, утверждения, риск и резюме по строгой JSON-схеме |

Используются официальные API. Автоматизация браузерных версий ChatGPT, Gemini
или Alice не входит в архитектуру.

## Объект мониторинга

Объект содержит:

- тип: бренд, человек или компания;
- название и варианты написания;
- до пяти поисковых запросов;
- регион поиска;
- период публикаций: 7, 14 или 30 дней;
- список официальных сайтов и профилей для определения контролируемых результатов;
- фиксированный набор промптов для AI-мониторинга.

## Сценарий сканирования

1. Backend создает запуск сканирования и фиксирует его параметры.
2. Для каждой сохраненной фразы отдельно запрашиваются Яндекс, Google через
   SerpApi и Wordstat. Исходная фраза сохраняется вместе с каждым ответом.
3. Результаты приводятся к общей модели материала: URL, источник, канал, дата,
   заголовок, сниппет, позиция и исходные метрики.
4. Из оценочной массы заранее исключаются известные реестры, справочники
   организаций и нетекстовые документы. Остальные URL передаются в Firecrawl;
   ошибка извлечения сохраняется отдельно и не выдается за анализ полного текста.
5. Выбранная в админке LLM проверяет извлеченный текст, идентичность объекта,
   значимость материала, тип источника, тональность, темы и риск. Справочные и
   незначимые материалы не включаются в итоговую оценку и раздел «Материалы».
6. По агрегированному пакету подтвержденных материалов, поисковой выдачи,
   Wordstat и доступных AI-ответов LLM формирует общую оценку до 500 символов,
   не более шести главных тем по важности и краткие рекомендации. Alice AI и
   ответ через OpenRouter получают все сохраненные запросы в общем контексте,
   без отдельного LLM-вызова на каждый ключ.
7. Результаты сохраняются как неизменяемый снимок. Изменения позиций и состава
   выдачи рассчитываются только относительно предыдущего снимка с теми же
   регионом, устройством и запросом.
8. Backlink-анализ не запускается, пока нет доступа к Ahrefs.

Повторные URL объединяются в один материал, но сохраняют все обнаружения,
позиции, запросы и каналы.

## Классификация источников

Источник классифицируется как `media`, `corporate`, `blog`, `aggregator`,
`ugc` или `unknown`. Учитываются Schema.org, автор, дата, рубрики, RSS,
редакционные контакты, архив публикаций, структура URL и общий профиль домена.

Категория `media` означает редакционный тип ресурса, а не юридически
подтвержденный статус СМИ. Юридическая отметка «зарегистрированное СМИ» может
присваиваться только домену из проверенного внутреннего справочника.

## AI-мониторинг

Для каждого объекта хранится до пяти поисковых запросов. Ответы AI сохраняются
вместе с сервисом, текстом и цитируемыми URL. Генеративный ответ ограничен
1000 символами; ссылки показываются внутри форматированного текста.

Yandex Generative Search используется для блока Alice AI, OpenRouter — для
отдельного ответа ChatGPT, SerpApi — для доступного Google AI Overview в Markdown.
Gemini и Ahrefs Brand Radar не запускаются. Ответ API является воспроизводимым
замером, но не гарантирует совпадение с персонализированным ответом пользователя.

Семантический анализ выполняется отдельно через OpenRouter и не подменяет
ответы AI-сервисов. Backend использует OpenAI-compatible endpoint
`POST https://openrouter.ai/api/v1/chat/completions`. Выбранная модератором
модель получает сниппет или извлеченный текст и возвращает JSON по фиксированной
схеме: релевантность, тип источника, тональность, тематики, ключевые утверждения,
риск, уверенность и краткое резюме. Идентификатор фактически использованной
модели фиксируется в каждом результате, а качество проверяется на размеченной
выборке до запуска интеграции.

## Backlink-граф

Анализ начинается с выбранного негативного URL:

1. Получаются ссылки и домены первого уровня.
2. Доноры группируются по корневому домену, IP, Class C, анкору и времени
   первого обнаружения.
3. Для подозрительных доноров запрашиваются backlinks второго уровня.
4. Граф ограничивается двумя уровнями и лимитами на число раскрываемых доноров.
5. Оцениваются общие IP и подсети, синхронность появления, повторяющиеся анкоры,
   взаимные ссылки, число исходящих ссылок, spam-признаки и качество доменов.

Система не утверждает принадлежность сайтов одному владельцу. Результат имеет
формулировку «признаки ссылочной сети» и уровень уверенности: низкий, средний
или высокий. Доказанная принадлежность возможна только после ручной проверки.

## Метрики и ограничения

- «Найденные материалы» означает материалы, обнаруженные выбранными источниками.
- Просмотры и пересылки доступны для Telegram. Для обычных сайтов охват не
  рассчитывается.
- Сумма просмотров Telegram не называется уникальным охватом.
- Контролируемый результат определяется только по списку официальных доменов и
  профилей объекта, а не по положительной тональности.
- Wordstat отражает спрос в Яндексе и не используется как частотность Google.
- Причинная связь между публикацией, ростом спроса и изменением выдачи не
  утверждается. Допустима только хронология совпавших событий.
- Изменение позиции, появление и исчезновение материала показываются после
  накопления минимум двух сопоставимых снимков.
- Тематики, тональность и риск являются модельной оценкой и должны быть
  обозначены как AI-анализ вместе с моделью и уровнем уверенности.

## Техническая схема

Реализация остается модульным монолитом в существующем стеке:

- React для интерфейса;
- Fastify для API и оркестрации сканирования;
- PostgreSQL для объектов, запусков, материалов, снимков, AI-ответов и графов;
- фоновый обработчик на таблице заданий PostgreSQL;
- без Redis, отдельного брокера очередей и микросервисов в первой версии;
- кэширование внешних ответов и извлеченных текстов;
- хранение сырого ответа провайдера для аудита и повторной обработки.

Основные группы данных: объекты и запросы мониторинга, запуски, поисковые
снимки, материалы и обнаружения, Telegram-посты, AI-ответы и цитаты,
LLM-анализы, профили источников, backlink-узлы и ребра.

## Ключи интеграций

Ключи добавляются модератором в отдельном разделе админки «API интеграции».
Доступен фиксированный список провайдеров: OpenRouter, Яндекс,
SerpApi, Ahrefs, TGStat и Firecrawl. Интеграция Яндекса использует один ключ
Yandex AI Studio для веб-поиска, генеративного поиска и Wordstat. Произвольный base URL из
интерфейса не принимается.

Ключи шифруются на сервере алгоритмом AES-256-GCM с ключом окружения
`INTEGRATION_SECRETS_KEY`. В API и интерфейс возвращаются только признак
подключения и последние четыре символа. В production переменная обязательна;
смена ключа окружения требует отдельной процедуры перешифрования сохраненных
секретов.

Для OpenRouter модератор задает model slug. Проверка подключения выполняется
через `GET https://openrouter.ai/api/v1/models` с Bearer-аутентификацией. Сам
LLM-вызов выполняется сервером; браузер API-ключ не получает.

Для Яндекса вместе с API-ключом хранится `folderId` каталога Yandex Cloud.
Оба значения доступны только серверным адаптерам. Проверка подключения
выполняет отдельные запросы к веб-поиску, генеративному поиску и Wordstat;
успех одного метода не маскирует ошибку другого. Проверочные вызовы могут
тарифицироваться Яндексом.

## Перед началом интеграции

Для запуска Ahrefs и TGStat отдельно подтвердить доступ, тарифы и бюджет.
Текущий сбор обрабатывает не более 100 уникальных несправочных URL за снимок;
пропущенное количество сохраняется и показывается в интерфейсе. Перед
увеличением лимита проверить стоимость Firecrawl и LLM на реальном объеме.
