# Настройки администратора

## Реализовано

- Главный администратор: существующий `admin@axioma.local`. Признак хранится в БД; обычный администратор не может назначать или отключать других администраторов.
- Главный администратор приглашает администраторов, модераторов и суперадминистраторов через существующую форму. Суперадминистратор имеет доступ ко всем рабочим разделам админки, но не управляет составом администраторов; это право остается только у главного.
- Модератору доступны очередь материалов, просмотр и решение по площадкам, проверка рекламодателей, а также собственные пароль и 2FA. API запрещает ему доступ к заказам, финансам, пользователям, аудиту, обращениям, интеграциям и управлению командой. Навигация показывает только доступные разделы.
- Персональная комиссия задается в финансовой вкладке пользователя. Для заказчика она заменяет стандартные 15% при создании нового счета на пополнение; для паблишера заменяет стандартное удержание из новых заказов. Ставка фиксируется в счете или заказе, изменение и возврат к стандартной ставке записываются в аудит.
- Приглашение администратора через существующий механизм доступа команды. При отзыве доступа аккаунт сохраняется, сессии прекращаются, действие записывается в аудит. Главного администратора заблокировать этим способом нельзя.
- Изменение собственного пароля с проверкой текущего пароля и завершением остальных сессий. Новый пароль: 12–128 символов.
- Двухфакторная защита через приложение-аутентификатор: QR-код, подтверждение настройки, одноразовые резервные коды, проверка при входе. Секрет хранится зашифрованным, резервные коды — в виде хешей. Повторное использование кода запрещено.
- Просмотр сессий и завершение остальных сессий.
- Удаление заявки паблишера из рабочего списка с сохранением записи и аудита. Приглашение по удалённой заявке перестаёт действовать. Уже созданный кабинет, площадки и доступ паблишера не изменяются.

## Существующие неподключённые настройки

- Код подтверждения по email: доставка ещё не подключена; выбор не включает фиктивную защиту.
- Настройки каналов Email/Telegram и операционных уведомлений остаются прототипными. Доставка и сохранение предпочтений требуют отдельного подключения.
- Форма «Параметры платформы» (комиссия, SLA модерации, срок ответа по спору) пока не сохраняет значения на сервер. Её текущий индикатор сохранения не является подтверждением изменения расчётов.

## Что необходимо согласовать перед расширением

1. Права обычных администраторов: сейчас они имеют общую операционную роль. Для разделения модерации, финансов и поддержки нужна утверждённая матрица прав, а не только новые подписи в интерфейсе.
2. Обязательность 2FA для администраторов и процедура восстановления при потере устройства и резервных кодов.
3. Политика сессий: длительность, повторная аутентификация перед финансовыми и критическими действиями.
4. Сохранение комиссии и сроков: область применения, дата вступления в силу, сохранение исторических условий уже созданных заказов.
5. События уведомлений, получатели и доступные каналы доставки.
6. Срок хранения аудита, доступ к журналу и выгрузкам, мониторинг подозрительных входов. Пароли, секреты 2FA и резервные коды в аудит не включаются.

Эти пункты являются анализом, а не разрешением добавлять новые элементы интерфейса. Перед изменениями использовать существующий аналог; если его нет — запросить решение пользователя.

## Эксплуатация

Ключ шифрования секретов 2FA использует существующий секрет интеграций. Его нужно сохранять между перезапусками и защищать вместе с резервными копиями; замена ключа без миграции секретов нарушит проверку кодов. Миграция назначает главным только уже существующий независимый аккаунт `admin@axioma.local`; для новой установки назначение главного администратора должно быть выполнено явно после создания аккаунта.
